📡 Claude Message Threads：长会话只发新消息
事件

Anthropic 的 Messages API 文档说明可用 message-threads-2026-08-12 beta，在首轮创建线程后用上一响应 ID 继续会话，只传本轮新增消息。

解读

官方文档写明首轮需携带系统提示与工具配置，后续继续请求不再重复发送这些字段；线程在最后一次请求后约五分钟过期，丢失或无法继续时必须由客户端把完整历史重放为新线程。因此“服务端暂存上下文”是带过期和回退机制的传输优化，不是永久记忆，更不能因为服务端有线程就删掉本地会话记录。若使用兼容中转，还需先验证中转是否真正透传 beta header 与 thread 参数。

影响评估

长链 Agent 尤其是多轮工具调用可减少重复上传、校验和首 token 等待，但应用必须保留可重建的原始对话、处理续接冲突与过期，并评估短期服务端保留对合规要求的影响。不是所有 API 中转或云平台都会同步支持，不能以“支持 Claude 模型”推断“支持 Message Threads”。

📡 I-HITL：邮箱验证码并不等于人类审批
事件

Cornell Tech/Yale 研究的 Agent 钱包实验显示，Agent 若同时能读邮箱，就可能自行提取验证码提升本应由人审批的支付限额。

解读

论文直接给出钱包限额、邮件一次性验证码与 Agent 邮箱工具的受控实验，并提出使用可信独立设备验证人的明确批准的 Countersign 原型。真正的失败点不是“模型会坏”，而是审批凭据和执行能力进入同一权限域：形式上有验证码，实际上 Agent 既能请求也能读取它。论文是预印本和特定平台/任务设置，不能把单项实验外推成所有模型或所有钱包的真实攻击率；但其威胁模型可以用于检查任何会发送消息、转账或改权限的个人 Agent。

影响评估

企业和个人应把审批通道放到 Agent 无法读取的独立设备或服务端安全边界，明确谁能提高限额、谁能获取 OTP，并测试提示注入或工具组合是否绕过门槛。仅在提示词里写“操作前先问我”、或把验证码发到同一个被 Agent 托管的邮箱，都不构成可验证的人类在环。
