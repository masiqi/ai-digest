🛠️ OpenGCUA
一句话

通义 MAI-UI 团队发布的通用电脑操作 Agent 开放技术栈预览，把 GUI、代码执行和跨设备接口放在同一框架里。

链接

https://github.com/Tongyi-MAI/OpenGCUA ↗

https://github.com/Tongyi-MAI/OpenGCUA/blob/main/QUICKSTART.md ↗

怎么玩

先阅读仓库 README 的开放范围与 QUICKSTART，不要把预览版当成已经发布完整模型权重的产品。macOS 14 以上准备 Python 3.11—3.14、uv、CuaDriver 和所需系统权限；若从源码装 SDK，还需 Rust/Cargo 与 Xcode 命令行工具。按仓库的示例配置一个自己有授权的模型端点，先用 OSWorld 集成示例或不涉及敏感账号的本地测试任务核对截图动作与代码动作的执行轨迹，再决定是否接入日常桌面工作。注意屏幕录制与辅助功能授权只给测试环境。

为什么值得关注

仓库明确把可访问性树、应用接口、Shell 与视觉界面视为同一电脑任务的多种执行路径，还提供初步 macOS harness、跨设备 SDK、评测轨迹和 OSWorld 参考实现。它不是单纯的“看图点鼠标”演示；不过当前版本标为 research preview，部署复杂度和安全边界都需要自己验证。

应用场景
  • 对比截图点击与代码操作解决同一桌面任务的成功率、步数和失败恢复。
  • 为自家 Agent 设计跨浏览器、桌面与手机的统一动作接口原型。

🛠️ api-bench
一句话

两个无第三方依赖的 Python 脚本，检测 Claude Messages / OpenAI Responses 网关的首字延迟、并发与提示词缓存。

链接

https://github.com/Okkmass/api-bench ↗

https://www.okkmax.com/tools/api-speed ↗

怎么玩

打开仓库选与真实接口模式相符的 messages_bench.py 或 responses_bench.py；先运行对应脚本的 --help，看全局参数、模型名、目标地址和四种子命令的排列，切勿把 OpenAI Chat Completions 误当 Responses 接口。用仅限自己有权测试的网关，密钥放 BENCH_API_KEY 环境变量，不要放在命令行或报告中；先用少量请求运行 bench，再试 cache 和 roll，最后以缩短采样间隔的 report 生成 HTML，对照错误分类、首字延迟及缓存命中。测试会实际扣额度，不用生产密钥大并发压测。

为什么值得关注

中转站“快”与“便宜”不能只看单次总耗时；首字延迟、长对话滚动缓存和缓存读写是不同工程问题。仓库把两种 API 协议拆成单文件脚本，还能在本机输出独立 HTML，便于把性能退化与宣传口径分开；目前仓库列出的不是 Chat Completions 模式的完整测试器。

应用场景
  • 比较自建中转与官方接口的首字延迟、成功率及长对话缓存表现。
  • 改网关配置后留存同参数 HTML 报告做回归对比。

🛠️ Agent Relay
一句话

用私有 Git 仓库中的 Markdown 任务文件，在本地与云端 Agent 之间做有状态的接力。

链接

https://github.com/robbin/agent-relay ↗

https://github.com/robbin/agent-relay/blob/main/README.zh-CN.md ↗

怎么玩

先读仓库 README、docs/protocol.md 与 docs/security.md，准备单独的私有任务仓库，不要把令牌、简历或客户数据塞进公开仓库。按照示例建 tasks/to-cloud 与 tasks/to-local，分别配置云端 webhook 和 macOS 本地同步定时器。写一条无敏感信息的测试 Markdown 任务，观察它从 pending、accepted 到 done 或 blocked 的变化，再检查同一文件内的结果内容和 Git 历史。收到 webhook 只是提醒，不代表任务已被执行；安装和授权前审查同步脚本与权限。

应用场景
