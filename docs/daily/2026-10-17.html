🛠️ Perplexity SPACE
一句话

把 Agent 或用户生成的代码放进隔离的 Firecracker microVM，并通过 HTTP API 管理执行与生命周期的开源平台。

链接

https://github.com/perplexityai/SPACE ↗

https://space.docs.perplexity.ai/guide/index.html ↗

怎么玩

先读仓库 docs/installation.md，准备文档要求的 Linux/Kubernetes 与虚拟化环境，再按安装指南在本地 Kind 集群部署服务并完成认证；接着跟着 docs/first-sandbox.md 创建模板和 sandbox，等待异步操作完成后建立命令会话、附着输出通道，执行一段无害的示例代码，读取退出码和输出，最后删除 sandbox。不要在未确认宿主机是否支持 Firecracker 的情况下直接把生产凭证塞进去；先在隔离测试机上检查网络权限、存储清理和并发上限。

为什么值得关注

SPACE 不是给 Agent 再包一层提示词，而是把不可信代码的实际执行搬到独立虚拟机，同时把环境模板、沙箱实例、命令会话与生命周期拆开。对于自建 Agent 平台，隔离边界、异步状态与输出回收比单次代码运行是否成功更重要；这份开源实现可以作为安全设计与故障恢复的对照样本。

应用场景
  • 让代码 Agent 跑用户提交的单元测试，同时隔离工作空间与宿主机。
  • 为多租户自动化任务提供可销毁的临时执行环境。

📡 Anthropic 内部用工：Agent 时长高于员工
事件

Anthropic 发布内部用工研究，称截至 2026 年 8 月互动式 Agent 工作时长约为员工工作时长的六倍，同时初级技术岗位招聘占比走低。研究：https://www.anthropic.com/research/employment-at-anthropic

解读

这是一家高度采用自家 AI 的公司的内部观察，不能直接外推为所有企业的普遍失业率，也不能把工作时长比理解为等效产能比。报告强调代码、销售与合同处理产出随工具采用增加，但人类注意力成为审读 Agent 产出的瓶颈；招聘经理更看重自主性与判断力。比「Agent 替代了多少人」更可操作的问题是：输出能否被采样检查、责任边界是否清晰、每位员工承载了多少校验负荷。

影响评估

软件团队可能先调整初级岗位任务结构、培训路径与审查工具，而不是简单减少所有招聘。Agent 运维、评测、日志可见性和质量门槛会直接影响组织能否吃到效率红利；教育机构也需要让新人练习判断、验证和协作，而不只练最容易自动生成的样板代码。
