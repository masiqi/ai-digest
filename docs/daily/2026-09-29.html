🛠️ Manus 2.0 / Cue：把个人 Agent 做成有身份的执行者
一句话

Manus 2.0 是一次架构和产品重做，加入 Manus Studio、Video Editor、Game Dev、Automations 与 Cloud Computer；独立应用 Cue 则让个人 Agent 拥有自己的电话、邮箱、钱包和电脑，在授权边界内持续完成生活与工作任务。

链接

https://manus.im/blog/introducing-manus-2-0 ↗

https://cue.im/ ↗

怎么玩

先打开 Manus 2.0 官网或下载桌面端，尝试用一个明确结果描述任务，例如“把这份产品资料做成 30 秒宣传片”或“把一个小游戏做成可分享的网页”。需要个人 Agent 场景时进入 Cue 官网，使用早期体验邀请码 MEETCUE（名额和平台可用性以页面实际状态为准），再给 Agent 配置允许使用的邮箱、电话、电脑工作区和预算。第一次建议从查资料、拟邮件、整理行程等可回滚任务开始；涉及付款、外发消息或修改文件时，逐项检查确认边界，不要一上来授予全部权限。

为什么值得关注

它不只是把聊天窗口换成 App，而是把 Agent 的“身份、工具、执行环境和持续工作”组合起来。官方同时展示了事件触发自动化、可编辑视频时间线、游戏多人云电脑和授权后的 Computer Use，说明产品竞争点正在从回答质量扩展到能否在真实服务之间把任务闭环。需要注意的是，Cue 仍处于早期体验，电话、支付和外部服务能力带来的安全与责任边界必须人工审查。

应用场景
  • 个人旅行、预约、邮件和日程的半自动办理。
  • 从产品 brief 到视频初剪、可编辑时间线和可分享小游戏的连续创作。

🛠️ OpenWorker：本地优先、交付成品的开源桌面 Agent
一句话

OpenWorker 是运行在桌面的开源 AI coworker，连接本地文件、终端、Slack、GitHub、日历等工具，目标不是只给建议，而是产出文档、报告、代码修复和可审阅的外部动作。

链接

https://github.com/andrewyng/openworker ↗

https://openworker.com/ ↗

怎么玩

在 macOS Apple Silicon 上直接从官网下载安装包，打开后配置自己的 OpenAI、Anthropic、Google、DeepSeek 等 API Key，或连接本地 Ollama。先选一个不涉及外部写入的任务，例如“检查这个仓库的依赖和 CI 风险并生成报告”，让它读取文件、运行检查并产出文件。确认结果后再尝试连接 GitHub 或 Slack；发送消息、运行命令、开 PR 等动作会进入审批步骤，先看差异、证据和目标对象，再决定批准。想研究实现，可 clone 仓库，重点看 coworker 后端、MCP 客户端和 Tauri/React 桌面壳。

为什么值得关注

它把“本地运行、模型自带、可审批动作、交付物落盘”放在一个完整产品里，且底层基于 aisuite 统一不同模型提供商，降低了被单一模型锁定的成本。官网展示的安全 coworker 还强调云环境只读、修复以 PR 形式交付，这种把发现、证据、补丁和审批拆开的设计，比单纯让 Agent 获得一把高权限终端更接近可控生产流程。

应用场景
  • 在本机完成代码审计、依赖检查并生成可审阅修复分支。
  • 把 Slack、GitHub、日历和本地资料汇总成真正可交付的工作成果。

🛠️ NVIDIA OpenShell：给自主 Agent 加上可审计的沙箱边界
一句话

OpenShell 是 NVIDIA 开源的自主 Agent 运行时，通过内核级隔离和声明式 YAML 策略限制文件、网络、进程和模型提供商凭据访问。

链接

https://github.com/NVIDIA/OpenShell ↗

https://docs.nvidia.com/openshell/latest/ ↗

怎么玩

先阅读官方 Overview 和 Quickstart，确认系统、内核与平台支持矩阵，再按官方安装方式部署。创建第一个 sandbox 时只声明一个测试仓库目录和必要的模型端点，使用网络策略禁止未批准的出站地址，用文件系统规则阻止访问 SSH key、云凭据和其他用户目录。运行 Claude Code、OpenCode 或 Codex 这类需要终端的 Agent，观察它能否完成编译、测试和读取允许文件，同时尝试访问禁止路径验证拦截结果。把 YAML 策略提交到版本库，变更前后用同一组测试记录审计结果；不要把真实生产凭据直接放进实验环境。

为什么值得关注

OpenShell 处理的是 Agent 进入真实系统后最容易失控的部分，而不是再做一个提示词护栏。官方把文件、网络、进程和 provider credentials 分成独立保护层，并把策略写成可审阅、可版本化的配置；这为企业运行编码 Agent、私有模型端点和长任务提供了比“相信模型会自律”更明确的控制面。它也提醒开发者：沙箱隔离必须覆盖侧信道、出站网络和凭据注入，而不只是限制当前目录。

应用场景
  • 在隔离环境中运行会安装依赖、改代码和调用工具的编码 Agent。
  • 为企业内部 Agent 建立最小权限、网络白名单和审计记录。

🛠️ Ming-Image-0.1-Design：面向海报、UI 和信息图的可编辑设计模型
一句话

Ming-Image-0.1-Design 是 6B 文生图模型，重点面向 UI、信息图、海报等文字密集设计，并支持 RGBA 透明背景；配套 Ming-Image 仓库还提供设计图层分解路线。

链接

https://huggingface.co/inclusionAI/Ming-Image-0.1-Design ↗

https://github.com/inclusionAI/Ming-Image ↗

https://huggingface.co/inclusionAI/Ming-Image-0.1-Design-Layer ↗

怎么玩

先打开模型卡确认硬件预算，再 clone 官方 Ming-Image 仓库并安装 requirements。使用仓库里的 prompt 示例运行 `python infer.py --model inclusionAI/Ming-Image-0.1-Design --task text-to-image --resolution 2048 --output-dir outputs/t2i`，先做一张带中文标题的活动海报或产品卡片。得到结果后再研究透明背景提示词，最后用 Design-Layer 模型和 layer-decompose 任务，把扁平设计拆成计划数量的 RGBA 图层。单张 48G 显存设备更现实；不要把“6B”误解成普通笔记本即可流畅运行，完整管线还包括多模态编码器、Connector 和 VAE。

为什么值得关注

它的差异不只是画面好看，而是把生成结果往设计工作流推进：文字、主体、贴纸和背景可以被当作可继续处理的设计结构，透明 RGBA 又方便进入海报、网页和视频合成。官方模型卡同时给出 companion repo、1024/2048 分辨率桶和图层分解模型，证据链比单条演示推文完整。不过显存门槛和推理速度仍然是个人部署前必须核实的现实成本。

应用场景
  • 活动海报、中文标题、产品 KV 和 UI 概念稿的首版生成。
  • 把平面设计拆成可独立调整的 RGBA 图层后继续合成。

Eleven v4 面向高表现力长内容，支持 90 多种语言、多个说话人、音效和脚本内情绪标签；v4 Turbo 面向实时对话，官方给出的中位推理延迟约 100ms、首字语音约 150ms。

链接

https://elevenlabs.io/v4 ↗

https://elevenlabs.io/docs/overview/models ↗

怎么玩

进入 Eleven v4 页面或 Playground，先用一段 30 秒中文旁白测试 `[whispers]`、`[laughs]`、`[excited]`、`[door slams]` 等自然语言标签，比较普通叙述、情绪叙述和多角色对白。需要长音频时，把同一角色放进多段文本，检查上下文 stitching 和重复生成后的音色稳定性。需要语音 Agent 时切换到 v4 Turbo 的 API 或 ElevenAgents，采用双向流式输入，让 LLM 生成到半句就开始回传音频；生产前要核验声音授权、语音克隆同意、语言口音、成本和 AI 生成音频标识。

应用场景
  • 有声书、课程、短视频和游戏角色的长内容配音。
  • 客服、预约、电话回访等需要低延迟和情绪变化的语音 Agent。
