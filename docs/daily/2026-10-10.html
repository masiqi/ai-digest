📡 Claude Dynamic Workflows / Managed Agents
事件

Anthropic 将 Dynamic Workflows 推向公测，主 Agent 可以按计划分阶段并行调度大量子 Agent，Managed Agents 也支持在沙箱中运行 Agent 任务。

解读

这代表 Agent 产品的竞争重点正在从“单个模型回答得好不好”转向“复杂任务能否拆解、并发执行、汇总并验证”。官方文档将 dynamic workflow 描述为由脚本编排多个子 Agent，适合代码库级排错、迁移、研究和审计；Managed Agents 则把环境配置、工具执行和事件流纳入运行时。对开发者来说，真正需要设计的是任务边界、共享上下文、失败重试和最终验收，而不是简单把子 Agent 数量做大。并行不等于可靠，缺少去重、权限和审查时，错误也会被并行放大。

影响评估

当“编排”变成产品能力，企业 AI 平台会更像一个带预算、权限、日志和恢复机制的任务操作系统。研发团队可以把大规模代码迁移、知识库核验和多来源研究拆成可复用流程，但 token 成本、状态管理、数据隔离和结果责任也会明显上升。短期内更值得关注的是可观测性和可中断恢复，而不是“最多能调度多少 Agent”的宣传数字。

解读

Agent 安全开始从提示词约束和人工确认，进一步下沉到操作系统与执行环境。OpenAI 的说明显示，Codex 命令从启动时就处于受限边界，子进程也继承限制；微软则把 Execution Containers 定位为面向不可信代码和模型生成工作负载的策略执行层。这样做的关键不是把 Agent 变得“不会犯错”，而是让错误最多影响被授权的项目目录、命令和网络范围。对本地编码而言，沙箱是生产力功能，也是安全基础设施。
