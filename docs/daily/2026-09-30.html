🛠️ Douchat
一句话

一个桌面 AI 工作空间，把云端模型、本地 Agent CLI 和人与 Agent 的群聊放到同一套联系人与对话界面里。

链接

https://github.com/thinkany-ai/douchat ↗

https://douchat.ai ↗

怎么玩

先访问官网下载适合自己系统的安装包；仓库说明提供签名桌面构建，源码试用也可以按 Quick start 操作。首次打开后登录 Douchat 账号，在联系人列表中查看云端 Agent 和本地 Agent，先开一个直接对话完成小任务，再创建群聊，把两个 Agent 拉进来，让一个负责拆解、另一个负责补充或检查。每个 Agent 都可以编辑身份、记忆、技能、权限和模型。若用源码开发，按仓库说明执行 npm ci、复制 .env.example 为 .env，再运行开发命令；不要把真实密钥提交进 .env。第一次建议只给它非敏感资料和小型代码任务，观察任务移交、上下文保留和失败处理。

为什么值得关注

它把“多个 Agent 各自有一套窗口、上下文和凭据”的碎片化体验，收敛成一个可回看的桌面工作区。官方仓库明确支持云端与本地 Agent、群聊、Agent 间消息和可编辑的 Markdown 身份/记忆；GitHub 当前能看到项目仍在持续更新。对已经使用 Codex、Claude Code 或其他 CLI 工具的人，价值不是再多一个聊天框，而是能在一个线程里组织协作，并把模型、权限和数据边界显式化。

应用场景
  • 让研究 Agent 查资料、代码 Agent 改项目，再由 Lead Agent 汇总结果。
  • 把本地 Agent 与云端模型放进同一联系人列表，比较隐私、速度和成本。

🛠️ Unsloth Laya Decision Model
一句话

在本地运行 Laya 决策模型，把文本转换成选择、是/否或分数，可通过兼容 Jev 的 API 供应用调用。

链接

https://unsloth.ai/docs/models/decision-laya ↗

https://unsloth.ai/download ↗

怎么玩

下载并安装 Unsloth Desktop，支持 macOS、Windows 和 Linux。打开 Settings → API → Decision API，开启 Serve requests，确认下载默认的 Multilingual 模型；官方文档给出的模型约 678 MB、最低 4GB RAM，支持 100 多种语言和 1024 token 上下文。然后在 API 页面复制 Access token，或者仅在 localhost 测试时开启 Keyless API access。向本地端点提交一段文本，并在请求中定义 team、refund、urgency 这类结构化决策，观察返回的选择、置信度、概率或分数。先用邮件分类、工单路由等无风险样例测试，再接入业务系统；GPU 只在需要更低延迟时打开。

为什么值得关注

传统 LLM 调用往往输出一段需要二次解析的自然语言，决策模型直接把“允许的选项”和概率作为接口契约，适合自动化系统消费。官方文档强调 CPU、统一内存和 GPU 都可运行，并提供 TypeSafe-compatible Jev API，因此可以在数据不出设备的前提下做分类、路由和标签。它不等同于通用聊天模型，价值在于可测量、可约束、可替换的决策节点；置信度仍需用自有标注集校准，不能直接当作业务正确率。

应用场景
  • 把客服工单分到 billing、technical、sales 等队列，并给紧急程度打分。
  • 在本地对邮件、Agent trace 或安全事件做初筛，减少敏感文本外发。

🛠️ Magpie
一句话

一个开源本地 AI Gateway，让 Codex、Claude Code、Gemini CLI 等 Agent 共享不同厂商和本地模型。

链接

https://github.com/yetone/magpie ↗

https://usemagpie.ai/ ↗

怎么玩

macOS、Windows、Linux 都可以先访问官网下载安装；也可以执行官网给出的安装命令 `curl -fsSL https://usemagpie.ai/install.sh | sh`，安装后使用 magpie 命令。打开菜单栏或 TUI，先在 Providers 中添加一个供应商，填写对应 Key；本地 Ollama 等服务可以不填云端 Key。再选择 Codex、Claude Code 或其他已安装 Agent，为它指定模型，必要时用 Profiles 保存“省钱/专注”等整套配置。Gateway 默认监听本机 `127.0.0.1:3425`，可以先用一个简单问答或代码任务确认流式输出和工具调用，再逐个切换正式工作流。密钥只在 Magpie 中配置，不要复制到项目环境变量或日志。

为什么值得关注

Magpie 解决的是 Agent 生态的协议错配：Codex 偏 OpenAI Responses，Claude Code 偏 Anthropic Messages，其他 CLI 又有自己的配置格式。官方页面说明它在本地做双向协议翻译，覆盖流式、工具调用和推理，并能精细修改 settings.json、config.toml、config.yaml 而保留注释、顺序和缩进。它是小体积原生应用，不是 Electron；对有多个订阅、多个中转和多个 coding Agent 的用户，能减少逐个改配置的成本，也方便按任务比较模型质量、延迟和花费。

应用场景
  • 用低价或本地模型跑日常代码阅读，让高价模型只处理关键架构任务。
  • 为不同 Agent 保存统一模型 Profile，比较同一任务在不同供应商上的效果。

一个本机运行的个人训练工作区，用 3D 人体、训练时间线、YAML 数据和 AI 对话整理训练计划与实际记录。

链接

https://github.com/liuchuan01/Fitness-OS ↗

怎么玩

按仓库 README 准备 Git、Node.js 24 和 npm 11，在项目根目录安装依赖并启动开发服务器；打开 `http://127.0.0.1:5173`。为避免误用仓库内的默认空工作区，先设置自己的 WORKSPACE_ROOT，再运行 `npm run dev`。首次使用先浏览 3D 人体和训练时间线，建立一个自己的工作区，录入一次训练、动作、组数和身体指标；然后试着用对话整理一个训练目标，检查内容是否写入可读的 YAML 文件。模型调用需要自行配置，建议先用虚构数据熟悉流程；正式使用前备份 fitness/，不要把 config/ 中的凭据提交到公开仓库。

为什么值得关注

它不是把健身问答套在聊天窗口上，而是把训练数据放到可读、可备份的 YAML 工作区，并把计划和实际完成分开，再通过本地服务校验写入。README 说明前端使用 React、TypeScript、Vite 和 Three.js，本地 Node 服务负责数据契约与写入，AI 会话由 DeepSeek Harness 提供；同时明确提示真实模型建档和生产部署仍未完成完整验收。因此它更适合观察“结构化个人数据+本地 Agent”的产品原型，不应被当作医疗或健身诊断系统。

应用场景
  • 为长期训练建立可迁移的动作、组次和身体状态档案。
  • 研究如何把结构化 YAML 数据与对话式训练计划结合。

🛠️ Raven
一句话

一个面向长任务和递归自我改进的多 Agent Harness，把研究、代码、设计和验证拆成可观察的多轮工作流。

链接

https://github.com/EverMind-AI/Raven ↗

https://evermind-ai.github.io/Raven/ ↗

怎么玩

先阅读官方 Quick Start，再在 macOS、Linux 或 WSL2 上安装；如果希望隔离环境，可按仓库 Docker 文档启动 Compose，并打开本地 WebUI。第一次不要直接交给它生产目录，而是配置一个低风险小任务，例如生成静态页面、整理本地资料或修一个独立测试。给任务写清验收标准、最大轮数、允许访问的目录和模型提供商，在 WebUI 里观察子 Agent、任务依赖、文件输出和验证结果。确认每一轮的变更都能回看、失败能停住后，再尝试代码修复或实验优化。项目 README 明确标注 pre-alpha，配置和界面可能快速变化。

为什么值得关注

Raven 的差异不只是“能调多个模型”，而是把 Memory、Planning、Capability、Action 等策略模块放进一个可持久化的 Harness，并配有文档、WebUI、Docker 和插件目录。官方展示了长轮次规划/开发/验证案例，但这些 showcase 不能等同于普适性能保证。真正值得拆解的是它如何记录轮次、隔离失败变更、保留长期记忆，以及把一次性提示变成带验收节点的可复用流程；高权限无人值守运行仍需要严格沙箱。

应用场景
  • 把长任务拆成可观察的规划、实现、测试循环，研究 Agent 如何持续修正。
  • 让研究、编程、设计 Agent 在同一个工作流中并行，再由验证节点汇总。

🛠️ qiaomu-obsidian-dev
一句话

一个给 Codex、Claude Code 等编码 Agent 使用的 Obsidian 插件开发 Skill，强调真实 Vault 验证和发布证据链。

链接

https://github.com/joeseesun/qiaomu-obsidian-dev ↗

怎么玩

确保 Node.js、Git 和一个独立的 Obsidian 测试 Vault 已准备好，然后执行 `npx skills add joeseesun/qiaomu-obsidian-dev`。安装后不要只让 Agent“写一个插件”，而是先要求它查 Obsidian 官方 API、示例和同类 GitHub 项目，再给出 Go、Revise、Stop 或 Contribute 结论。进入实现阶段，让它把插件装进测试 Vault，重载并执行真实交互；发布前分别核对构建、GitHub Release 资产、官方社区插件目录和客户端可安装状态。仓库的 references、evals、scripts 和 tests 可作为检查入口，最后把 GitHub Release 与官方市场可用性分开记录。

为什么值得关注

应用场景
  • 用 Agent 辅助开发、调试、评审和发布 Obsidian 插件。
  • 对已经能构建但无法稳定安装或上架的插件做发布链路审计。

🛠️ LaTeX Autofill
一句话

一个完全离线的 Obsidian 社区插件，用中文或英文关键词补全常用 LaTeX 模板，并支持 Tab 跳转占位符。

链接

https://meta.appinn.net/t/topic/92634 ↗

怎么玩

在 Obsidian 1.7.2 或更高版本打开 Settings → Community plugins，关闭受限模式后搜索并安装 LaTeX Autofill；若搜索不到，再从开发者自荐帖进入官方安装信息。新建或打开 Markdown 笔记，在行内公式或 `$$...$$` 环境中输入“定积分”“矩阵”“偏导数”，也可以输入 integral、matrix、partial，按回车插入完整模板，再用 Tab/Shift+Tab 在占位符间移动。遇到不记得命令的情况，打开插件的 Σ 搜索窗口，回车插入或使用 Ctrl/⌘+Enter 复制。先在测试笔记里确认快捷键与现有编辑器插件没有冲突。

为什么值得关注

它的定位很克制：不是调用 AI 猜公式，而是离线、可预测地把关键词映射到模板，因此不会把隐私笔记发送到云端，也更容易复现结果。开发者介绍称内置约 236 条常用写法和约 1000 条命令表，已上架 Obsidian 社区插件目录。对需要在 Obsidian 中长期写数学内容的人，可靠的占位符编辑体验可能比一次性生成复杂公式更实用。

应用场景
  • 在数学、物理、统计学习笔记中快速插入规范公式环境。
  • 给不熟悉 LaTeX 命令的学生提供离线模板入口，降低持续记忆成本。

🛠️ YODAS v3
一句话

ESPnet 发布的超大规模多语言语音数据集，提供超过 110 万小时音频及转写、翻译和时间戳元数据。

链接

https://huggingface.co/datasets/espnet/yodas3 ↗

https://huggingface.co/blog/espnet/yodasv3 ↗

怎么玩

先在 Hugging Face 数据集页阅读许可、目录结构和元数据字段，再按研究规模选择下载，不要直接把整个数据集拉到本机。数据按语言和 WebDataset shard 组织，单个 tar 约 8GB；可以先只取 zh 或 en 的一个 metadata parquet，检查 transcript、translation_en、length 和时间戳字段，再用 Hugging Face datasets 或 Parquet 工具做抽样统计。做 ASR、TTS 或语音表示实验时，先按语言、时长、转写存在性和音频质量过滤，建立小型验证集后再扩展。使用和再发布前按 CC-BY-3.0 及论文要求保留署名，并注意网页抓取音频的质量和语言标签并非绝对准确。

为什么值得关注

YODAS v3 的价值不只是数据量大，还提供语言、时长、声道、估计带宽和句子/词级时间戳等可筛选元数据。官方资料称它覆盖 100 多种语言，约 75% 音频有转写，非英语数据中约 60% 有英文翻译，约 95% 转写包含词级时间戳，适合构造更可控的训练和评测子集。工程难点会从“找不到数据”转移到清洗、采样、版权遵循和弱标签噪声控制。

应用场景
  • 训练或评测多语言 ASR、TTS、语音表示和跨语言对齐模型。
  • 按语言、时间戳和音频质量构造可复现实验子集，研究长尾语言覆盖。

📡 OpenAI DevDay 2026：个人 Agent、云端 Codex 与开放生态一起推进
事件

OpenAI 在 9 月 29 日 DevDay 发布 Dots、云端 Codex、Decisions API、Codex CLI 更新、代码审查与 Marketplace 等一组产品能力。

解读

这次发布的关键不是单个新模型，而是把“持续在线的个人 Agent”“远程可复用的开发环境”和“让模型做结构化选择的 API”放在一个产品组合里。Dots 被定位为可持续承担任务的 Agent，云端 Codex 则把开发环境从本机扩展到手机和云端；Decisions API 试图让应用在选项集合中返回决定，而不是每次生成长文本。对开发者来说，工作流会从一次请求一次响应，转向状态、权限、工具、环境和人工批准共同组成的长期系统。

影响评估

软件产品的竞争点会从“接入哪个模型”向“谁能把 Agent 安全地嵌入真实工作”迁移。个人 Agent 需要读取邮件、文件、浏览器和第三方应用，隐私与授权边界会变成核心产品能力；云端 Codex 和自动代码审查会降低协作门槛，但也会放大权限配置、供应链和审计要求。企业选型时应同时比较任务成功率、可恢复性、数据保留、工具调用成本和人工接管路径，而不是只看 benchmark。

📡 GPT-6.1 Sol：把高能力 Agent 推理压到更低的 API 成本
事件

OpenAI 发布 GPT-6.1 Sol，官方称其在 Agentic coding、computer use 和专业工作上接近 Astra，标准输入/输出价格约为 Astra 的五分之一，并提供 gpt-6.1-sol API。

解读

Sol 的价值在于把“能完成复杂任务”的模型从高价旗舰档拉到更适合批量运行和长流程编排的成本区间。官方页面给出的价格是每百万 token 输入 2 美元、缓存输入 0.10 美元、输出 10 美元，并列出代码、复杂 PDF、自动化工作流、电脑操作和科学任务评测。真正落地时，平均成本还取决于上下文复用、工具失败重试、推理强度、人工复核和任务是否需要 Astra 级别的极限能力。

影响评估

Agent 产品可以更大胆地把规划、工具调用和验证拆成多轮，而不必每一步都使用最贵模型；同时，低价高能力会加快客服路由、文档处理、代码维护和后台自动化的规模化。对团队而言，应该建立按任务类型分层的模型路由和成本账本，独立测量成功率、延迟、缓存命中、工具调用次数与错误恢复，不要直接把厂商 benchmark 当作自己的生产 SLA。

📡 Anthropic 警告 GLM-5.3 的网络安全滥用风险
事件

Anthropic 发布研究称，其在隔离环境中测试 GLM-5.3 与 GLM-5.3-Flash 时观察到较强的漏洞利用与攻击程序开发能力，并认为防护容易被绕过。

解读

Anthropic 的报告不是对真实世界攻击事件的独立取证，而是其自设沙箱、评测方法和安全立场下的研究结果；因此“能在测试环境完成 exploit”与“现实中已经造成同等规模危害”必须分开。报告关注的是模型能否把公开漏洞信息、补丁和攻击链组合起来，尤其是较小模型也可能被用于已知漏洞的 N-day 利用。它把开源模型的可得性、默认安全限制和滥用门槛重新放到同一张风险表上。

影响评估

安全团队需要把模型评测从“会不会写代码”升级为“能否形成可执行攻击链、是否会泄露工具调用、限制能否被提示绕过”。开源模型发布者如果只展示通用能力而缺少滥用测试，可能面对更高的供应链和监管压力；防守方则可把同类模型用于离线补丁验证、代码审计和漏洞复现，但必须严格隔离目标、凭据和网络出口。当前最稳妥的结论是风险信号增强，不是简单宣布某模型等于现实攻击者。
