https://github.com/SoMarkAI/OXR ↗

https://free-oxr.somark.ai ↗

怎么玩

最快的验证方式是打开免费演示页，上传一份包含表格、公式或双栏排版的非敏感 PDF，分别检查 Markdown 的阅读顺序和 JSON 的元素类型、坐标，再与自己已有的解析器逐页对照。如果需要可控部署，到仓库阅读 README，克隆代码并下载 SoMarkAI/OXR-1.0 权重，按部署说明启动本地服务；用提供的 /v1/parse/sync 接口上传测试文档，指定 markdown 和 json 两种输出。免费 API 排队且不保证稳定，生产资料与敏感文件应优先在自建环境测。

为什么值得关注

官方明确区分了可替换的版面分析模块和内容识别/阅读顺序能力，支持识别表格、公式、代码块、化学结构等多类元素；它不只是 OCR 文本转写。官方宣称的多个基准领先来自其公开比较，尚应以自己的中文扫描件、试卷和合同样本复核；代码与模型权重已公开，适合做真实的 RAG 前处理对比。

应用场景
  • 将含表格和脚注的内部知识库 PDF 转成结构化片段，再检查检索问答是否能定位原页。

一句话

链接

怎么玩

硬件不足时先在官方演示页面做对照：给模型连续多轮提供互相冲突的用户偏好，再在后续轮次问它当前采用哪条偏好，同时记下跨会话是否真的保留状态。具备 Linux、CUDA 及足够显存的环境再按仓库 inference 目录安装 server 依赖，下载完整的 MemT-1.0-Nano 权重，使用 start_memt_nano.sh 指向模型目录启动 SGLang；用仓库的 Python 客户端创建两个独立会话，交替写入不同事实并检验是否串话。README 示例使用两张 GPU，普通 Mac 不宜直接照搬部署。

为什么值得关注

它把动态局部记忆与可训练的超记忆放进计算图，而不是简单地把聊天记录塞回长上下文或依赖外部向量数据库。论文报告在 128K 历史下，相对完整上下文 KV 缓存有推理速度及状态存储优势；这是作者给出的实验结果，不等于所有任务能摆脱检索或保证准确记忆。对需要长期交互的 Agent，状态隔离与遗忘行为更值得亲测。

应用场景
