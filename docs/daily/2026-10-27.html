🛠️ proc-cli
一句话

面向人和编码 Agent 的跨平台进程/端口 CLI，能查端口占用、进程来源和残留子进程。

链接

https://proc-cli.com/ ↗

怎么玩

先在官网阅读安装和命令页，macOS 可按首页说明使用 brew install yazeed/proc/proc；打开一个自己启动的临时开发服务，先运行 proc on :3000 看端口归属，再用 proc why :3000 查父进程链，必要时用 proc in . 限定当前项目范围。涉及停止进程，先运行 proc free :3000 --dry-run 预览对象并确认 PID、命令行和工作目录，确定是自己的测试服务后才执行；给 Agent 接入时优先使用 --json 并保留审批门槛，不要让它根据端口号误杀共享服务。

为什么值得关注

常见 Agent 工具调用把 lsof、ps、kill 的输出拼接起来解析，平台差异与表格解析很容易造成误判；proc 给出一致的目标语法、JSON 输出与 dry-run，让诊断和执行可以分离。网站列出返回码和受控操作，但是否能准确识别特定容器或远程进程仍要在目标环境自测。

应用场景
  • 开发端口被占时先定位旧测试进程，再安全释放端口。
  • 排查 Agent 测试后留下的长时间运行子进程，保留机器状态证据。
