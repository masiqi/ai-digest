🛠️ Spotcat：macOS 原生启动器，把应用、文件、网页和 AI 放进一个入口
一句话

Spotcat 是免费开源的 macOS 原生启动器，用 ⌥Space 呼出，可模糊搜索应用与文件、打开网页、调用 AI 对话，并通过 HTML/JS 扩展增强工作流。

链接

https://github.com/thinkany-ai/spotcat ↗

https://spotcat.ai ↗

https://github.com/thinkany-ai/spotcat/releases/latest ↗

怎么玩

先从 Releases 下载最新的 Spotcat-0.4.0.dmg，打开后把应用拖进 Applications；首次启动后按 ⌥Space，输入应用名或文件名并回车。想试 AI，在 Settings → Models 添加 Anthropic 或 OpenAI-compatible 服务商、API key 和模型；想试扩展，可进入 Settings → Extensions 安装，或按 README 的 manifest.json + index.html 结构写一个本地扩展。建议先用“file *.pdf”搜索下载目录，再用一个带 ai 权限的简单扩展验证上下文对话，最后检查模型 key 仍只保存在本机。

为什么值得关注

它不是套壳网页，而是 Swift/AppKit 原生浮窗，支持 Apple silicon 与 Intel，且扩展接口采用普通 HTML/CSS/JS，降低了 macOS 工具开发门槛。官方 README 还明确说明 API key 以 600 权限保存在本机，GitHub 发布页提供签名和公证的通用安装包；对已经在 Raycast、Spotlight 与浏览器之间频繁切换的人，实际价值在于把搜索、AI 与小工具组合到同一个键盘入口。

应用场景
  • 用统一快捷键查找项目文件、启动开发工具，并把选中的文本交给 AI 解释。
  • 为团队写一个内部 HTML/JS 小扩展，把编码规范、翻译或 URL 编解码接到日常搜索流。

🛠️ SeshBuddy：本地浏览和审查 Claude Code、Codex 等 AI 编程会话
一句话

SeshBuddy 是 macOS/Windows 桌面工作台，读取多个 AI 编程 CLI 已写入磁盘的会话日志，提供统一浏览、全文搜索、归档、代码 diff 与本地流量检查。

链接

https://github.com/huangy7/seshbuddy ↗

https://seshbuddy.huangy.top/en/ ↗

怎么玩

先打开项目主页下载 macOS 或 Windows 版本；如果想从源码试验，准备 Node.js 20+、稳定 Rust 工具链和对应 Tauri 前置依赖，执行 git clone、npm install、npm run tauri dev。启动后让它扫描本机已有的 Claude Code、Codex、Gemini、Antigravity、WorkBuddy 或 DSH 会话，再用统一搜索检索某次提示词、工具调用或代码块。需要审查网络请求时，单独启用 seshbuddy-proxy，先观察请求/响应、延迟和 token 用量，确认无误后再恢复原始 endpoint。

为什么值得关注

很多 Agent 工具把会话当成一次性聊天，SeshBuddy 把它们当成可复盘的工程资料：本地 Tantivy 索引覆盖 prompt、回复、工具调用和代码块，Monaco 提供 diff，桌面助手还能引用具体会话来源。官方说明会话不离开本机、无账号和 telemetry；可选出站请求范围也写得很清楚，因此更适合做成本追踪、失败复盘和团队编码审计，而不是只看一次生成结果。

应用场景
  • 搜索过去生成过的配置、命令或 bug 修复，避免重复让模型探索。
  • 在合并前集中查看 Agent 改动、请求延迟和 token 使用，建立轻量审查流程。

🛠️ DeepSeek Harness：一切皆插件的开源 Agent 运行框架
一句话

DeepSeek Harness（dsh）是 DeepSeek AI 发布的开发者预览版 Agent harness，把模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 组织为可替换插件。

链接

https://github.com/deepseek-ai/deepseek-harness ↗

https://deepseek.com/harness/ ↗

https://deepseek-harness.github.io/deepseek-harness/ ↗

怎么玩

准备 Node.js 后，先用 npx @deepseek-ai/dsh web 启动本地 Web UI，默认访问 http://127.0.0.1:3080；如果要改源码，克隆仓库后执行 pnpm install、pnpm run build、pnpm dsh web。首次体验建议先使用标准模式跑一个小型代码任务，再切换 PTC 模式观察模型如何用 Code Mode SDK 组合多步工具调用；随后打开 Trajectory 视图检查系统提示、工具调用、子 Agent 调度和上下文注入，最后再按官方文档尝试安装一个社区 dsh-plugin。

为什么值得关注

它把“Agent 能力如何组装”从框架内部实现问题变成配置与插件问题，允许替换模型、工具、沙箱和 UI，而不必改核心源码。官方介绍还强调追加式会话日志、恢复/分叉/检索/回放共享同一事件流，以及标准、PTC、极简、创造四种运行模式。这使它更像可观测的 Agent 基础设施，而不仅是又一个聊天界面；但项目仍是 developer preview，存在兼容性破坏，生产使用应隔离环境。

应用场景
  • 为不同任务组合不同工具、权限和模型，做可复现实验型 Agent。
  • 研究工具调用轨迹、子 Agent 和上下文注入，构建企业内部 harness 原型。

🛠️ Paseo DSH Direct：让 DeepSeek Harness 接入多 Agent 编排桌面
一句话

paseo-dsh-direct 是 Paseo 的 DeepSeek Harness 原生 Provider 插件，跳过 ACP 桥接，直接调用本地 dsh，并保留流式输出、审批卡片、会话导入与斜杠命令。

链接

https://github.com/Jecvay/paseo-dsh-direct ↗

https://github.com/getpaseo/paseo ↗

怎么玩

先安装并确认本机 dsh 与 Paseo daemon 可用，再在 Paseo 的 Settings → Plugins → Install Plugin 中粘贴 npm:paseo-dsh-direct；如果本机 dsh 属于 0.1.x，应按 README 使用对应 release/0.1 分支，0.2.x 则使用默认 npm 线。安装后创建 DeepSeek Harness provider 对话，选择配置好的模型与 preset；如果要本地开发，可 clone 仓库、npm ci、npm run build，再执行 paseo plugin install "$PWD/paseo-dsh-direct"。测试时先确认 dsh 版本匹配，避免把会话交给错误兼容线。

为什么值得关注

普通 ACP 适配往往会损失原生 Agent 的交互语义，而该插件把 dsh 的思考流、工具审批、用户提问、slash command 和会话恢复映射到 Paseo 自己的界面。官方 README 明确列出了 0.1.x/0.2.x 兼容关系，并说明插件使用独立 paseo profile，不修改 Paseo 或 DSH 核心；这为“终端 Agent + 可视化编排 + 原生审批”提供了一个相对低侵入的组合方式。

应用场景
  • 用桌面界面统一管理多个 DSH Agent 会话和审批动作。
  • 把已经存在的 DSH 原生会话导入 Paseo，继续运行而不丢失会话身份。

🛠️ 乔木 RSS：在 DeepSeek Harness 里阅读文章并带上下文追问
一句话

qiaomu-rss-dsh 是 DeepSeek Harness 社区插件，把 RSS/Atom 订阅、原文/译文/改写阅读和原生 AI 伴读放进同一工作区。

链接

https://github.com/joeseesun/qiaomu-rss-dsh ↗

https://github.com/joeseesun/qiaomu-rss-dsh/releases/latest ↗

怎么玩

先准备 DeepSeek Harness 0.2.0-rc.2，下载 Release 中的 .tgz 与同名 .sha256 文件，在下载目录执行 shasum -a 256 -c qiaomu-rss-dsh-0.5.2.tgz.sha256，然后用 dsh plugin --profile desktop add "$PWD/qiaomu-rss-dsh-0.5.2.tgz" 安装；使用 Web profile 时把 desktop 换成 web。重启对应 profile 后打开“乔木 RSS”，从精选频道或探索订阅添加 RSS/Atom，打开文章并点击魔法棒，让右侧原生对话带着文章全文上下文回答。先不配置模型也可以阅读已有内容，生成译文或伴读回答则需要宿主模型配置。

为什么值得关注

它把“信息摄取”和“Agent 对话”连接起来：文章、选中文本、译文和改写版本都能成为当前会话上下文，用户不用来回复制网页。官方 README 同时披露了实际验证范围、插件不是 DeepSeek 官方维护、订阅数据存储位置以及没有 Obsidian 式笔记功能，边界比许多演示型插件更清楚。对长期读技术 RSS 的人，最值得试的是从一篇文章直接追问、比较和复盘，而不是单纯生成摘要。

应用场景
  • 每天阅读 AI/工程 RSS，直接在文章旁追问术语、实现细节和反例。
  • 把播客或博客订阅集中管理，再让 Agent 按文章上下文生成中文学习笔记草稿。

一句话

pdfcn 提供基于 Takumi 与 Forme 的免费 React PDF 组件和 blocks，支持表格、表单、图表、发票与报告等可组合文档。

链接

https://github.com/shadcn-labs/pdfcn ↗

https://pdfcn.vercel.app/docs ↗

https://pdfcn.vercel.app/docs/installation ↗

怎么玩

在一个 React 项目中先打开官方文档的 Installation 页面，按指引安装依赖；也可以直接浏览 Components/Blocks，挑一个 invoice、table 或 report 组件，把源码复制进自己的项目后替换数据与主题。建议先做一个最小发票页，分别试 Takumi 与 Forme 两种渲染基础，再用浏览器中的 live preview 检查分页和字体；确认输出稳定后，再把组件封装成项目自己的模板。由于它采用 shadcn/ui 相近的 registry 思路，团队可把组件当作源码资产维护，而不是依赖一个不可见的模板服务。

应用场景
  • 在 SaaS 后台把发票、运营报表和合同附件统一成可复用 React 组件。

📡 Gemini 4 Argon：长输出上限把前沿模型竞争推向长时程任务
事件

X List 多条信息称 Google 发布 Gemini 4 Argon，并将单次输出上限从 64K 提升到 100 万 tokens，首批面向 Fairwind 网络安全防御人员开放。

解读

如果这些首发规格最终由 Google 官方文档完整确认，核心变化不是又一次跑分领先，而是模型开始针对“一个任务持续很久、一次性产出完整代码库或报告”的代理工作流设计。百万级输出会降低长任务中断、摘要压缩和上下文拼接的频率，但也会把验证、成本、权限和失败回滚变成更大的工程问题。目前本日报能确认的是 Google 官方 X 帐号确实发布了 Gemini 4 Argon 的长时程软件工程定位；定价、全面开放时间与全部跑分仍应以官方开发者文档为准。

影响评估

模型供应商的竞争会从“回答一轮问题”继续转向长任务吞吐、上下文保持和代理可靠性。开发团队若要评估这类模型，不应只测单题准确率，还要测长代码库修改的中途恢复、输出截断、工具调用预算和审查成本；百万 token 上限也不等于应该无条件生成百万 token，任务规划与分段验收仍是必要控制点。

📡 GLM-5.3 安全争议：开源前沿能力与可滥用风险同时下沉
事件

X List 转述 Anthropic 对 GLM-5.3 的网络安全能力与防护弱点进行评测，称其接近前沿端到端自主漏洞利用能力且自由可获取。

解读

这条线索的价值在于提醒行业：当高水平网络安全能力以可下载模型形态出现时，风险边界不再由少数 API 网关控制，模型权重、微调、工具权限和部署环境会共同决定实际危险程度。当前可确认的是推文引用了 Anthropic 研究页面，不能仅凭转述判断完整测评方法、样本和结论；因此更适合作为安全工程议题而不是“某模型一定危险”的定论。部署类似模型时，应把网络访问、代码执行、凭据读取和自动化攻击链拆开审计。

影响评估

开源模型评测会从通用能力榜单扩展到能力—防护双轴，模型发布者需要提供更可重复的红队方法、缓解措施和部署建议。企业采购或自部署时，不能只看许可证与 benchmark，还要验证模型在隔离网络、最小权限、人工审批和日志留存条件下的行为；研究者也应区分“模型有能力”与“模型在真实环境可造成影响”。
