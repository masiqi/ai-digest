🛠️ Papilot：在 PDF 上审阅 LaTeX 论文
一句话

把 PDF 批注定位到 LaTeX 源码，让 Agent 修改论文，并对每处排版后的变化逐条接受或拒绝。

链接

https://github.com/cu1ch3n/papilot ↗

怎么玩

先准备 Node.js 22.22+、Git 和完整 TeX 发行版，再运行 npm install -g papilot、papilot demo；浏览器访问 http://127.0.0.1:7274，在侧栏选择 PDF，先用自带的示例论文练习圈选公式、写修改意见、查看排版前后差异与 Accept/Reject。接入自己的论文时，项目必须是 Git 仓库中的 LaTeX 工程，先用 papilot doctor --repo 检查依赖，再按 README 登录 Codex 或配置 Claude API。务必先从副本试验，别把尚未审阅的改动直接合并到投稿版本。

为什么值得关注

通常的 AI 改论文只给 TeX 文本 diff，而作者真正关心的是“印出的那一页发生了什么”。Papilot 借助 SyncTeX 把 PDF 选区映射回源码，并用独立 Git worktree 隔离任务、逐条展示排版差异；这是面向论文审阅而非普通聊天的一套可核对交互。

应用场景
  • 和导师沟通公式、图表或段落修订，逐条核对排版效果。
  • 给长篇 LaTeX 讲义做错字与结构检查，保留可拒绝的审阅记录。

🛠️ personal-agent-dossier：Agent 搬家档案
一句话

把个人 Agent 的职责、定时任务全文、长期记忆和依赖装进可校验的单文件档案。

链接

https://github.com/AidaShika/personal-agent-dossier ↗

怎么玩

先 git clone https://github.com/AidaShika/personal-agent-dossier，在仓库内阅读 SKILL.md 和 SPEC.md；第一次不要导出自己的真实 Agent，先执行 pip install -r requirements.txt，运行 python3 tools/dossier_check.py examples/scribe.dossier.md 检查示例结构、指纹和敏感数据扫描。之后把整个仓库交给待迁移 Agent 作为 Skill，请它导出 .dossier.md；在目标平台只做 dry-run 导入，核对职位、时区、任务提示词及记忆逐项是否降级，再决定是否真正写入。真实档案不要公开上传，绝不要复制凭据。

为什么值得关注

迁移 Agent 不只是拷贝一段人设，最容易丢的是定时任务的完整指令、记忆类别和“不要做什么”。这个格式对 null 与空列表作严格区分，并要求导入方报告无法承接的项目；指纹只校验 name/title/role，不能代替任务与记忆的逐项比对，边界写得很清楚。

应用场景
  • 把一个已经运行多项日常任务的 Agent 从旧平台迁移至独立 profile。
  • 团队更换 Agent 运行框架时先审计职责、任务和记忆的损失清单。
