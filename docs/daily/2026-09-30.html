🛠️ Douchat
一句话

一个桌面 AI 工作空间，把云端模型、本地 Agent CLI 和人与 Agent 的群聊放到同一套联系人与对话界面里。

链接

https://github.com/thinkany-ai/douchat ↗

https://douchat.ai ↗

怎么玩

先访问官网下载适合自己系统的安装包；macOS Apple Silicon、Intel、Windows 和 Linux 都有公开构建。首次打开后登录 Douchat 账号，在 Local agents 中刷新已安装的 Claude Code、Codex、Gemini、OpenCode 或 Hermes 等 CLI，再创建一个带明确角色和权限的 Agent。可以先开一个直接对话，让它完成一个小任务；随后建群，把两个 Agent 拉进来，用 @ 指定负责人或让 Lead Agent 分派工作。若想用自己的模型，在设置里添加 OpenAI-compatible 或 Anthropic-compatible provider。源码试用则按仓库执行 npm ci、cp .env.example .env、npm run dev；不要把真实密钥提交进 .env。

为什么值得关注

它把“多个 Agent 各自有一套窗口、上下文和凭据”的碎片化体验，收敛成桌面工作区。官方仓库明确支持群聊、主题、Agent 间私信、任务移交、本地 CLI、定时任务和自定义模型；聊天记录、记忆和配置主要留在本机，且本地文件工具有目录限制。对已经使用 Codex、Claude Code 等工具的人，最大的价值不是多一个聊天框，而是可以在一个可回看的线程里组织协作和权限边界。

应用场景
  • 让研究 Agent 查资料、让代码 Agent 改项目，再由一个 Lead Agent 汇总结果。
  • 把个人模型 API、已登录的本地 Agent CLI 和团队群聊放进同一台电脑，减少复制上下文。

🛠️ Unsloth Laya Decision Model
一句话

在本地运行 Laya 决策模型，把文本转换成选择、是/否或分数，可通过 Jev API 供应用调用。

链接

https://unsloth.ai/docs/models/decision-laya ↗

怎么玩

下载并安装 Unsloth Desktop，支持 macOS、Windows 和 Linux。打开 Settings → API → Decision API，开启 Serve requests，确认下载默认的 Multilingual 模型；它约 678 MB、最低 4GB RAM，支持 100 多种语言和 1024 token 上下文。然后在 API 页面复制 Access token，或者仅在 localhost 测试时开启 Keyless API access。向本地端点提交一段文本，并在请求中定义 team、refund、urgency 这类结构化决策，返回结果会包含选择、置信度、概率或分数。先用邮件分类、工单路由等无风险样例测试，再接入业务系统；GPU 只在需要更低延迟时打开。

为什么值得关注

传统 LLM 调用往往输出一段需要二次解析的自然语言，决策模型直接把“允许的选项”和概率作为接口契约，适合自动化系统消费。官方文档还强调 CPU、统一内存和 GPU 都可运行，并提供 TypeSafe-compatible Jev API，因此可以在数据不出设备的前提下做分类、路由和标签。它不等同于通用聊天模型，价值在于可测量、可约束、可替换的决策节点。

应用场景
  • 把客服工单分到 billing、technical、sales 等队列，并给紧急程度打分。
  • 在本地对邮件、Agent trace 或安全事件做初筛，减少敏感文本外发。

🛠️ Magpie
一句话

一个开源本地 AI Gateway，让 Codex、Claude Code、Gemini CLI 等 Agent 共享 DeepSeek、Kimi、GLM、Qwen、OpenRouter、Ollama 等模型。

链接

https://github.com/yetone/magpie ↗

https://usemagpie.ai/ ↗

怎么玩

macOS、Windows、Linux 都可以先访问官网下载安装；也可以在终端执行 `curl -fsSL https://usemagpie.ai/install.sh | sh`，安装后使用 `magpie` 命令。打开菜单栏或 TUI，先在 Providers 中添加一个供应商，填写对应 Key；本地 Ollama 等服务可以不填云端 Key。再选择 Codex、Claude Code 或其他已安装 Agent，为它指定模型，必要时用 Profiles 保存“省钱/专注”等整套配置。Gateway 默认监听本机 `127.0.0.1:3425`，可以先用一个简单的问答或代码任务确认流式输出和工具调用，再逐个切换正式工作流。密钥只在 Magpie 中配置，不要复制到项目环境变量或日志。

为什么值得关注

Magpie 解决的是 Agent 生态的协议错配：Codex 偏 OpenAI Responses，Claude Code 偏 Anthropic Messages，其他 CLI 又有自己的配置格式。官方说明它在本地做协议翻译，覆盖流式、工具调用和推理，并能精细修改 settings.json、config.toml、config.yaml 而尽量保留注释、顺序和缩进。它还是轻量原生应用，不是 Electron；对有多个订阅、多个中转和多个 coding Agent 的用户，能显著减少逐个改配置的成本。

应用场景
  • 用低价或本地模型跑日常代码阅读，让高价模型只处理关键架构任务。
  • 为不同 Agent 保存统一的模型 Profile，比较同一任务在不同供应商上的质量、延迟和成本。

🛠️ AI Fitness OS
一句话

一个本机运行的个人训练工作区，用 3D 人体、训练时间线、YAML 数据和 AI 教练整理训练计划与实际记录。

链接

https://github.com/liuchuan01/trainng ↗

怎么玩

按仓库 README 准备 Git、Node.js 24 和 npm 11，然后执行 `git clone https://github.com/liuchuan01/trainng.git`、`cd trainng`、`npm ci`。先把个人数据放在代码仓库之外，例如设置 `export WORKSPACE_ROOT="$HOME/my-fitness-workspace"`，再执行 `npm run fitness -- init` 和 `npm run dev`，用浏览器打开 `http://127.0.0.1:5173`。首次使用进入配置后台，在 DeepSeek 卡片填入自己的 API Key；没有 Key 仍可浏览人体和训练界面，但无法使用 AI 对话。之后建立训练档案，确认 AI 整理的摘要，再讨论第一份计划；训练结束时单独录入真实动作、组次和负重，不要把计划当成已完成记录。

为什么值得关注

它不是把健身问答套在聊天窗口上，而是把训练数据放到可读、可备份的 YAML 工作区，并把“计划”和“实际完成”分离，再通过本地程序校验写入。README 同时明确标注了当前边界：单人本地试用，模型上下文会发送到服务商，真实模型建档和生产部署仍未完全验收。这种把数据主权、状态模型和 AI 对话拆开的设计，比单纯生成一份训练计划更适合作为个人 Agent 产品原型观察。

应用场景
  • 以自己的器械条件和训练时间建立长期训练档案，复盘肌群分布和动作记录。
  • 研究“结构化个人数据 + AI 教练 + 本地工作区”的产品形态。

🛠️ Raven
一句话

一个面向递归自我改进的多 Agent Harness，能组织研究、代码、设计和无人值守工作流，并把每轮结果交给下一轮验证。

链接

https://github.com/EverMind-AI/Raven ↗

https://evermind-ai.github.io/Raven/ ↗

怎么玩

macOS、Linux 或 WSL2 可先执行 `curl -fsSL https://raven.evermind.ai/install.sh | bash`；若希望隔离环境，克隆仓库后执行 `docker compose -f docker/docker-compose.yml up`，再打开 `http://localhost:18793`。安装完成后先配置一个低风险的小任务，例如让 Raven 生成一个静态页面或整理一份本地资料，并给出明确的验收标准和轮数上限。通过 `raven web` 打开 WebUI，观察任务依赖、子 Agent、文件输出和验证结果；确认工作流可控后，再尝试代码修复或实验优化。它目前仍是 pre-alpha，必须检查每轮变更和权限，不要直接给生产目录或敏感凭据。

为什么值得关注

Raven 的差异不只是“能调多个模型”，而是把 Memory、Planning、Capability、Action 四个策略模块拆开，并让 Curator 在验证通过后改进 Agent Harness。官方展示了 42 轮规划/开发/验证完成 Godot 射击游戏，也展示了 7 轮训练实验和工程仿真；这些是项目自述的 showcase，不应当等同于普适性能保证。对 Agent 开发者而言，真正值得拆解的是它如何记录轮次、隔离失败变更、保留长期记忆，以及把一次性提示变成可复用的验收流程。

应用场景
  • 把长任务拆成可观察的规划、实现、测试循环，研究 Agent 如何持续修正。
  • 让研究、编程、设计 Agent 在同一个 DAG 中并行工作，再由验证节点汇总。

🛠️ qiaomu-obsidian-dev
一句话

一个给 Codex、Claude Code 等编码 Agent 使用的 Obsidian 插件开发 Skill，强调真实 Vault 验证和发布证据链。

链接

https://github.com/joeseesun/qiaomu-obsidian-dev ↗

怎么玩

确保 Node.js LTS、GitHub CLI 和一个独立的 Obsidian 测试 Vault 已准备好，然后执行 `npx skills add joeseesun/qiaomu-obsidian-dev`。安装后不要只让 Agent “写一个插件”，而是明确要求它先查 Obsidian 官方 API、示例和同类 GitHub 项目，再给出 Go、Revise、Stop 或 Contribute 结论。进入实现阶段后，让它把插件装进测试 Vault，重载并执行真实交互；发布前分别核对构建、PR/CI、GitHub Release 资产、官方社区目录和客户端可安装状态。仓库自带 `validate_skill.py`、`audit_release.py` 等只读检查脚本，可以按 README 对版本、资产大小、SHA-256 和公开 Release 做回读。

为什么值得关注

它针对的是 AI 编程最容易被忽略的最后一公里：能编译不代表真实宿主能用，Release 存在也不代表用户能安装。Skill 把 API 调研、竞品和许可证比较、状态所有权、生命周期、真实 Vault fixture、公开资产回读串成一个门禁流程，尤其适合 Obsidian 这类插件运行时差异明显、移动端边界复杂的生态。它的价值不在“多写几行代码”，而在把交付从模型自报完成改成证据驱动验收。

应用场景
  • 用它从零开发或审查 Obsidian 的阅读、RSS、AI、编辑器增强插件。

🛠️ LaTeX Autofill
一句话

一个完全离线的 Obsidian 社区插件，用中文或英文关键词补全常用 LaTeX 模板，并支持 Tab 跳转占位符。

链接

https://meta.appinn.net/t/topic/92634 ↗

怎么玩

先在 Obsidian 1.7.2 或更高版本打开 Settings → Community plugins，关闭受限模式后搜索并安装 LaTeX Autofill；也可以从插件作者的公开介绍进入安装信息。新建或打开 Markdown 笔记，在行内公式或 `$$...$$` 环境中输入“定积分”“矩阵”“偏导数”，或输入 integral、matrix、partial 等关键词，按回车插入完整模板，再用 Tab/Shift+Tab 在占位符间移动。遇到不记得命令的情况，用插件提供的 Σ 搜索窗口查找，回车插入或使用 Ctrl/⌘+Enter 复制。建议先在测试笔记里确认快捷键与现有编辑器插件没有冲突。

为什么值得关注

它的定位很克制：不是调用 AI 猜公式，而是离线、可预测地把关键词映射到模板，因此不会把隐私笔记发送到云端，也更容易复现结果。项目介绍称内置约 236 条常用写法和约 1000 条命令表，覆盖理工科笔记中频繁出现的积分、矩阵、微分和符号输入。对需要在 Obsidian 中长期写数学内容的人，可靠的占位符编辑体验可能比一次性生成复杂公式更实用。

应用场景
  • 在数学、物理、统计学习笔记中快速插入规范公式环境。
  • 给不熟悉 LaTeX 命令的学生提供离线模板入口，降低持续记忆成本。

🛠️ YODAS v3
一句话

ESPnet 发布的超大规模多语言语音数据集，提供超过 110 万小时音频及转写、翻译和时间戳元数据。

链接

https://huggingface.co/datasets/espnet/yodas3 ↗

https://huggingface.co/blog/espnet/yodasv3 ↗

怎么玩

先在 Hugging Face 数据集页阅读许可、目录结构和元数据字段，再按实际研究规模选择下载，不要直接把整个数据集拉到本机。数据按语言和 WebDataset shard 组织，单个 tar 约 8GB；可以先只取 `zh` 或 `en` 的一个 metadata parquet，检查 transcript、translation_en、length 和时间戳字段，再用 Hugging Face datasets 或 Parquet 工具做抽样统计。做 ASR、TTS 或语音表示实验时，先根据语言、时长、转写存在性和音频质量过滤，建立小型验证集后再扩展。使用和再发布前要按 CC-BY-3.0 及论文要求保留署名，并注意网页抓取音频的质量和语言标签并非绝对准确。

为什么值得关注

YODAS v3 把多语言语音实验的“数据起步成本”大幅压低：官方资料称它覆盖 100 多种语言，约 75% 音频有转写，非英语数据中约 60% 有英文翻译，约 95% 转写包含词级时间戳。它不仅是数量大，还提供语言、时长、声道、估计带宽等可筛选元数据，便于构造更可控的训练和评测集。真正的工程难点会从“找不到数据”转移到清洗、采样、版权遵循和防止弱标签噪声污染。

应用场景
  • 训练或评测多语言 ASR、TTS、语音表示和跨语言对齐模型。
  • 按语言、时间戳和音频质量构造可复现实验子集，研究长尾语言覆盖。

📡 OpenAI 把常驻个人 Agent 推向主产品：Dots
事件

OpenAI 在 DevDay 2026 介绍 Dots，把能够持续工作、使用云端电脑和浏览器、连接外部应用的 Agent 推向个人与企业工作流。

解读

官方介绍把 Dots 定义为“always-on agents”，重点不再是一次问答，而是记住用户偏好、持续推进任务、在关键节点请求批准，并在出错时尝试补救。X 上关于“无限额度”和订阅是否扣量的说法相互矛盾，不能直接采信；更稳妥的事实是，OpenAI 官方另文确认它是持续工作的 Agent 产品，并在合资格市场面向 Pro、Business Premium 等计划开放，企业、教育和医疗需要管理员开启 beta。它代表产品竞争从模型能力转向长期上下文、浏览器操作、责任边界和“在用户不在线时继续执行”。

影响评估

个人助理一旦拥有自己的浏览器、应用连接和长期记忆，隐私泄露、错误操作和授权撤销会成为产品成败的核心，而不只是模型聪不聪明。对开发者而言，新的竞争壁垒可能是任务状态、审批点、审计记录和失败恢复；对用户而言，必须区分“能自主推进”与“可以无监督地替你做高风险决定”。

事件

📡 Anthropic 警告 GLM-5.3 的网络安全滥用风险
事件

Anthropic 发布研究称，其在隔离环境中测试 GLM-5.3 与 GLM-5.3-Flash 时观察到较强的漏洞利用与攻击程序开发能力，并认为防护容易被绕过。

解读

Anthropic 的报告不是对真实世界攻击事件的独立取证，而是其自设沙箱、评测方法和安全立场下的研究结果；因此“能在测试环境完成 exploit”与“现实中已经造成同等规模危害”必须分开。报告关注的是模型能否把公开漏洞信息、补丁和攻击链组合起来，尤其是较小模型也可能被用于已知漏洞的 N-day 利用。它把开源模型的可得性、默认安全限制和滥用门槛重新放到同一张风险表上。

影响评估
