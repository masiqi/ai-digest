🛠️ huashu-art-motion：把艺术风格变成可复用动画 Skill
一句话

这是一个给 coding agent 使用的艺术动画 Skill，把 35 种艺术风格、9 种解说视频语法、参数化片段和可运行的代码引擎打包起来，让“做一段会动的画”从一次性提示词变成可以继续迭代的工程资产。

链接

https://github.com/alchaincyf/huashu-art-motion ↗

怎么玩

先安装 uv、ffmpeg 和 Playwright Chromium，再执行 `npx skills add alchaincyf/huashu-art-motion`，让 Claude Code、Codex 或其他兼容 Agent 读取仓库里的 SKILL.md。第一次不要直接追求完整成片：先从 README 的样片选一个风格，要求 Agent 只做一帧静态设计；确认构图、颜色和角色层次后，再运行对应 scene，让镜头、角色、背景和转场动起来。接着把自己的口播整理成镜头表或 JSON spec，选择白板、Vox、动态文字、财经图表等语法，最后用仓库提供的 qa.py 检查稳定性、帧效率、动感和流畅度。需要注意，完整渲染需要本机准备浏览器和字体，仓库中的角色形象与示范素材也有单独的使用边界。

为什么值得关注

它的亮点不只是“用 Claude 生成动画”，而是把风格配方、镜头运动、转场机制、参考片拆解和数字化 QA 都沉淀成可复用资产。这样换题材时不必重新从零描述审美，Agent 还能沿用已经验证过的绘制与验收方法；对做科普、课程、短视频和产品演示的人，价值在于把偶然的惊艳结果变成可重复的生产管线。

应用场景
  • 把一段口播快速转换成带节奏、带图形和角色动作的科普视频。
  • 为产品发布、课程讲解或短视频账号建立可持续复用的视觉模板。

🛠️ Qiaomu UI Learn：在 Obsidian 里补齐 UI 审美与 Vibe Coding 词汇
一句话

这是一个 Obsidian 插件，把 13,500+ 个真实设计案例、双语 UI 词典、44 种风格图鉴、审美测验和可复制的复刻 Prompt 放进一个本地学习工作台。

链接

https://github.com/joeseesun/qiaomu-ui-learn ↗

怎么玩

如果还没有等待社区插件审核，可以用 BRAT 添加 `joeseesun/qiaomu-ui-learn`，或者从仓库构建后把 main.js、manifest.json 和 styles.css 放到 `<vault>/.obsidian/plugins/qiaomu-ui-learn/`。打开插件后先从图库按分类浏览，遇到喜欢的页面用收藏和标签建立自己的参考集；再进入 UI 词典，搜索组件正式名称或自然语言描述，查看实时标本、API 速查、AI Prompt 和 Debug Prompt。想提升长期记忆，就用风格图鉴与审美测验做间隔复习；真正开始 Vibe Coding 时，在灯箱里复制“复刻 Prompt”，必要时连同 HTML 源码一起交给 Agent，并把过程保存成 Obsidian 笔记。插件说明称评分、收藏和测验进度写在本地 data.json，联网主要用于按需加载缩略图和打开原页。

为什么值得关注

很多 Vibe Coding 失败不是模型不会写 CSS，而是需求方无法准确说出想要的组件、间距、风格和交互。这个插件把“看得多、叫得准、说得清、能复现”串在一起，既是学习工具，也是给 Agent 提供设计上下文的素材库。它还把提示词和 HTML 复刻入口放在同一工作流里，比单纯收藏截图更容易直接转成可执行任务。

应用场景
  • 为网页、移动端或后台项目建立自己的视觉参考库与设计词汇表。
  • 在交给 Claude Code、Codex 等 Agent 前，先用样例和复刻 Prompt 把审美要求具体化。

🛠️ Waza：给 Claude Code、Codex 等 Agent 加一套工程习惯
一句话

Waza 是一个 MIT 开源的 Agent Skill 集合，把需求质疑、UI 设计、发布检查、根因调试、写作、资料学习、网页阅读和 Agent 健康审计拆成八个可调用的工程工作流。

链接

https://github.com/tw93/Waza ↗

怎么玩

在全局环境执行 `npx skills add tw93/Waza -a claude-code codex cursor -g -y`，或者只安装需要的单个 Skill。装好后不要把它当成万能规则，而是按任务阶段调用：准备开发前先用 `/think` 逼自己把目标、约束和验收标准说完整；做界面时用 `/ui`；遇到回归先用 `/hunt` 找根因，确认后再修；完成后用 `/check` 审差异、测试、发布准备和项目约束。需要快速看论文、网页或 PDF 时用 `/read`，做陌生领域调研时用 `/learn`，维护复杂 Agent 配置时用 `/health`。建议把项目自己的测试命令、目录边界和发布门禁写进项目说明，Waza 负责流程习惯而不是替代项目事实。

为什么值得关注

Waza 解决的是 Agent 输出“看起来完成、实际上不可验收”的老问题。它把工程师原本依赖经验的动作显式化，并且每个 Skill 都有明确触发时机和结果边界；八个小而清晰的入口，比堆一大套泛化规则更容易在不同 Agent、不同仓库之间迁移。对个人开发者尤其有用，因为它把审查、调试和研究也纳入了编码循环，而不是只优化生成第一版代码。

应用场景
  • 给个人或小团队建立统一的 AI 编程前置思考、调试和发布检查流程。
  • 在 Claude Code、Codex、Cursor、Pi 等多个 Agent 之间复用同一套工程习惯。

🛠️ H-JEPA：把视觉表示学习推进到分层世界模型
一句话

H-JEPA 是一个可运行的 PyTorch 研究代码库，围绕分层 Joint-Embedding Predictive Architecture 提供 masked-patch 自监督学习、SIGReg 端到端训练和动作条件世界模型三种模式。

链接

https://github.com/jonwiggins/H-JEPA ↗

怎么玩

先阅读论文 https://arxiv.org/abs/2610.06805，再克隆仓库并按 README 配置 Python 3.11/3.12、PyTorch 2.0+ 与依赖；不建议一上来跑大规模训练，先执行测试子集确认环境。仓库支持 CUDA、Apple Silicon 的 MPS 和 CPU，可以从默认 masked-patch SSL 配置开始，观察多层级表示与 FPN 融合的输出；如果目标是研究预测式世界模型，再切换到 SIGReg 或 action-conditioned 配置，阅读 AdaLN-Zero predictor 和 CEM latent-space planner 的参数。官方仓库明确说明目前没有预训练权重，主要用于从头训练和研究复现，因此在 Mac 上更适合小数据集、结构验证和单元测试，不要把一次小规模运行误读成完整能力评测。

为什么值得关注

它把视觉表征、长时程预测和动作规划放到同一套可切换框架里，方向上比“逐帧生成下一张画面”更接近 Agent 需要的世界模型。多尺度层级允许高层规划抽象目标、低层处理局部动态；同时支持 MPS 让更多研究者可以在消费级 Apple Silicon 上做结构实验。现阶段它仍是无预训练权重的研究代码，价值主要在可读架构和可复现实验，而不是开箱即用的机器人能力。

应用场景
  • 学习 JEPA、世界模型、表征学习和潜空间规划的代码实现。
  • 在视觉控制或机器人研究中验证分层表示与动作条件预测的组合方式。

🛠️ Prompt Motion：把 Opus 5.5 动画案例变成可检索的 Prompt 素材库
一句话

Prompt Motion 是一个展示 Claude Opus 5.5 动画视频的网页集合，案例页提供创作者、视频和部分 Prompt/Skill 入口，适合直接拆解别人如何要求模型做运动图形。

链接

https://prompt-motion.com ↗

怎么玩

先在首页按缩略图浏览不同案例，不要只看成片效果；打开案例页，记录它使用的画幅、时长、视觉风格、镜头节奏和是否采用代码绘制。挑一个与自己目标接近的案例，把 Prompt 复制出来后，先改成“只产出分镜表和验收标准”，要求 Agent 列出每个镜头的时长、画面元素、文字、声音和转场，再让它生成第一版。第二轮只改一个变量，例如把横屏改成竖屏、将商业广告换成科普主题或加入自有品牌素材，然后对比前后结果。这个站适合用来建立自己的 Prompt 组件库，但案例是社区作品，涉及人物、音乐、品牌素材时仍要自行检查版权和可发布性。

为什么值得关注

它提供了一个比泛泛的“Opus 很强”更可操作的观察窗口：用户可以从真实成片反推提示词结构、渲染方式和工作流组合。对做内容的人，最有价值的不是照抄单条 Prompt，而是比较不同案例如何处理故事板、镜头时序、代码动画、配音和素材调用，从而形成自己的可重复模板。

应用场景
  • 为产品宣传、课程片段和短视频寻找可运行的运动图形提示词起点。
  • 研究单次提示、分镜驱动和代码生成三种视频制作方法的差异。

🛠️ Nano Banana 2.1：更适合实际编辑流程的 Gemini 图像模型更新
一句话

Google 官方文档确认 `gemini-nano-banana-2.1` 是稳定模型 ID，支持文本、图像、视频、PDF 输入，图像和文本输出，并提供图像生成、Thinking、搜索 grounding、1K/2K/4K 等能力。

链接

https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1 ↗

怎么玩

先进入 Google AI for Developers 的图像生成文档，确认自己的 API 账号和配额，再用稳定模型 ID `gemini-nano-banana-2.1` 发起一个最小请求。第一轮用一张产品图做局部编辑，明确写出“保留主体、只修改背景或局部文字”；第二轮在同一对话中换比例、换背景和补充排版要求，观察多轮一致性；第三轮测试 2K 或 4K 输出，并把复杂任务拆成草图、精修、文字校正三个阶段。官方能力表还显示它支持 PDF/视频输入与搜索 grounding，但不支持 function calling、URL context 和 audio generation，接入自己的自动化管线前要按这个边界设计。免费体验则可通过 Google 相关产品入口尝试，API 生产使用需以官方当前价格和配额为准。

为什么值得关注

图像模型真正进入工作流，关键不只是一张图“好不好看”，还包括局部编辑、主体一致性、文字渲染、输入类型和成本。2.1 的官方模型页把稳定 ID、尺寸、能力边界和批处理支持写清楚，开发者可以据此做可重复测试，而不是只凭社交平台截图下结论。尤其是多轮编辑与中文排版，适合拿真实业务素材做 A/B，而不应只用漂亮的概念图评估。

应用场景
  • 产品图、海报、信息图和社交媒体素材的局部改图与多轮迭代。
  • 把 PDF、视频帧或参考图片纳入图像生成和编辑流程。

🛠️ Pi Harness：把个人 Agent 编程环境整理成可迁移 Harness
一句话

Pi Harness 是一个围绕 Pi Coding Agent 的个人配置仓库，包含工具、提示词、命令、Hooks、Skills 和多模型 Agent 编程相关的工程组织方式。

链接

https://github.com/aliou/pi-harness ↗

怎么玩

先克隆仓库，阅读 AGENTS.md、commands、hooks、tools 和 skills 目录，确认哪些规则依赖作者本地环境；不要直接覆盖自己的全局配置，先复制一份到独立测试项目中。选择一个最小任务，例如让 Agent 修改一个小模块、运行测试并生成 review，逐项观察它如何组织上下文、调用命令和处理失败。再把对自己有用的提示词和 Hook 单独迁移，替换模型、路径、包管理器和权限策略；每迁移一个组件都跑一次真实任务并保留日志。它的 README 已明确提示这是高度个人化、可能“不适合你”的 setup，所以正确玩法是把它当作架构样本和实验台，而不是无脑安装包。

为什么值得关注

随着个人 Agent 从“聊天问答”走向长任务编程，决定体验的往往是上下文、命令、恢复策略、审查和多模型切换，而不是单个模型名称。Pi Harness 把这些隐含配置公开出来，方便开发者研究一个成熟个人工作台如何分层；同时它也提醒我们，Harness 的价值与本地目录、权限和工作习惯强绑定，迁移时必须逐项验证。

应用场景
  • 设计自己的多模型编程 Agent 工作台、Hooks 和代码审查命令。
  • 研究如何把提示词、工具、恢复流程和项目上下文组合成长期可用的个人 Harness。

📡 OpenAI 一次公开 722 篇 AI 数学稿件，形式化验证成为关注点
事件

X List 转述 OpenAI 将一个内部未发布模型产生的 722 篇数学稿件、372 组结果公开；外部报道也确认了这一数量级，OpenAI 官方仓库同时公开了十个 Lean 4 形式化证明。

解读

这件事真正值得看的不是“论文数量”这个营销数字，而是成果是否能被数学共同体逐项阅读、复核、引用和修订。The Verge 报道称这些稿件还带有部分推理摘要、计算量估计和尝试统计，并提到数学与 AI 顾问组织曾建议实验室披露模型、提示词和计算成本。OpenAI 的 ten-proofs 仓库则把十个结果写成 Lean 4 文件，给出 Lake 构建方法和独立检查入口。两者共同说明，AI 科研的竞争点正在从“模型声称解决了多少问题”转向“能否留下机器可核验、社区可复用的证据链”；但 722 篇稿件的最终数学价值仍需要专家逐项审阅，不能把发布等同于全部结论已经被学界接受。

影响评估

如果这种开放方式持续，研究机构会更重视形式化证明、可复现实验、推理过程和计算预算的同步交付，AI 生成科研成果也可能从一次新闻发布变成可持续维护的公共仓库。反过来，稿件规模过大、作者贡献与训练数据来源不清，也会增加审稿、归因和学术伦理压力。对普通开发者而言，最现实的变化是 Lean 等形式化工具会更常出现在 AI 辅助数学和软件验证工作流中，而不是只属于理论计算机科学圈。

📡 量化评估从“文件精度”转向“显存里留下多少专家”
事件

MinLiBuilds 分享本地测试：同一模型、同一张 48GB 显卡、同属 Q4 档位，不同量化方案在 128K context 下速度可能相差 1.72 倍；驻留 expert 数量成为新的观察指标。

解读

这是一条来自社区实验的工程信号，不等同于经过独立复现的通用基准，但它指出了 MoE 本地部署经常被忽略的瓶颈：量化文件能否塞进显存只是第一关，剩余显存能容纳多少常用 expert、上下文长度如何改变缓存和换入换出，都会影响实际 decode 速度。也就是说，单看 Q4、Q3 这样的名义精度，无法预测某台机器上的端到端体验。GSQ、RCO 和 IQ 系列方法的价值，需要结合模型、后端、上下文、batch 和显存布局实测，不能只凭一张速度截图下结论。

影响评估

本地模型选型会从“下载最小文件”转向“精度损失、总内存、驻留专家、上下文吞吐”四项联合优化，量化工具也可能更强调硬件感知和工作负载感知。对个人开发者而言，未来评测同一个模型应至少记录显卡、后端、上下文长度、冷启动与稳定 decode 速度；对模型发布方而言，提供多种量化与显存占用说明会比单列参数量更有决策价值。

📡 AI 订阅的价格战正在逼用户区分“会员额度”和“真实推理成本”
事件

X List 讨论 Anthropic、OpenAI 的订阅层级、Token 配额与推理成本，称高阶套餐调整后同样预算能买到的有效使用量差异明显。

解读

这组内容来自社交平台转述，部分数字引用 SemiAnalysis 等第三方分析，但本次没有完成 Agent Reach 补充核验，因此不把“某家一定便宜五倍”当作已证实事实。可确认的行业方向是：长上下文、Agent 长任务和高推理强度正在让订阅产品出现更细的额度、速度和模型路由差异；用户看到的月费并不等于平台承担的固定成本，平台也会通过限速、模型切换、峰值限制和高价档位管理算力。比较服务时应记录实际完成的任务数、等待时间、可用模型、上下文长度和失败重试，而不是只看宣传 Token 数。

影响评估

AI 产品的竞争会从单纯比月费，转向比“每个可验收任务的成本”和“高峰期是否稳定”。个人用户应把真实工作流拆成可测样本，团队则需要把订阅额度、API 费用和本地模型的维护成本放进同一张账；对厂商来说，透明披露额度规则和模型路由会越来越影响信任。这里的具体价格与比例仍应以各家官方页面和独立实测为准。
