🛠️ Alma Relay（自建远程中继）
一句话

为桌面 Alma 的手机远程访问自建转发节点，把中继部署在自己的 Cloudflare Workers 或服务器上。

链接

https://github.com/yetone/alma-relay ↗

怎么玩

先在项目 README 的 Deploy 中选择 Cloudflare Workers 或 Docker 路线；前者准备 Cloudflare 账号，后者准备可用域名、DNS 和 80/443 端口，再照各自部署文档启动服务。用 HTTPS 地址访问 /healthz 检查服务状态，在桌面 Alma 的 Settings → Remote Access 选择自建中继并填入地址，随后用手机 Alma 重新扫描配对二维码。若是团队共用节点，按文档配置注册密钥，先在测试环境验证 WebSocket、重连和访问授权，再考虑放入日常远程工作流；旧配对需重新扫描。

为什么值得关注

仓库明确提供 Node 与 Workers/Durable Objects 两套中继实现；桌面主动连出，不要求给电脑开放公网端口。其文档称默认开启端到端加密，中继只处理密文，但自建并不等于自动完成安全审计：公开地址、注册密钥、TLS 与配对码撤销仍要自己管理。

应用场景
  • 在外用手机查看家里桌面 Alma 的 Agent 任务进度并远程处理。
  • 团队把转发节点放到自己控制的区域，以便测试延迟和信任边界。

怎么玩

先打开仓库 README 的在线 gallery，在浏览器逐个预览特效、改配色与镜像参数；若做网页游戏，可按文档运行 npm i github:patch-gg/pixelfx，再从包里选效果接入渲染逻辑。非网页项目则克隆仓库，在项目目录执行 README 给出的 node tools/render.mjs ice/frost-nova --sheet 示例，生成透明 PNG 帧表及 JSON 描述，再导入 Godot、Unity 或其他支持精灵表的引擎。先从单个效果打通导出和帧率，再批量替换已有占位素材。

怎么玩
